# PickMe GO V2.3-A Limited Public Wallet Pilot Report

## Summary

GO V2.3-A limited public wallet pilot framework is implemented for a controlled Gwanda-only wallet pilot.

This phase enables the backend framework for wallet deposits, wallet balances, wallet ride payments, platform-fee collection evidence, settlement recording evidence, reconciliation recording, audit records, risk monitoring, daily reporting, and kill-switch enforcement for an approved pilot cohort only.

It does not activate nationwide launch, public launch, public withdrawals, provider auto-settlement, mass onboarding, frontend contract changes, ride lifecycle changes, or websocket contract changes.

Architecture remains:

```text
Supabase = Storage
Go = Everything Smart
```

## Architecture Review

V2.3-A follows the established V2.2 governance model:

```text
Supabase stores pilot programs, cohort records, transaction evidence, reconciliation reports, fraud events, and kill-switch state.
Go owns cohort validation.
Go owns Gwanda-only authorization.
Go owns transaction-limit enforcement.
Go owns kill-switch enforcement.
Go owns reconciliation classification.
Go owns fraud-event validation.
Go owns pilot metrics and evidence generation.
Admin endpoints expose JSON reports only.
```

No wallet logic was moved into SQL triggers, Supabase functions, frontend code, or websocket contracts.

## Wallet Controls

Go validates:

```text
participant is enrolled
participant is active
participant type matches the operation
city is Gwanda
pilot program is active
pilot is inside start/end dates
rider and driver cohort limits are not exceeded
wallet balance limit is not exceeded
daily transaction limit is not exceeded
monthly transaction limit is not exceeded
requested wallet operation is not kill-switched
```

Failures reject the wallet pilot operation before mutation.

## Reconciliation Controls



## Operational Procedures

```text
1. Apply additive wallet pilot schema.
2. Keep nationwide/public launch controls disabled.
3. Create one planned Gwanda wallet pilot program.
4. Confirm program limits are 20 riders and 10 drivers.
5. Enroll only board-approved Gwanda riders and drivers.
6. Activate pilot only after finance, risk, operations, and CTO checks.
7. Monitor /admin/pilot/cohort daily.
8. Monitor /admin/pilot/transactions throughout operating hours.
9. Generate daily reconciliation reports.
10. Investigate any variance_detected report immediately.
11. Record failed payments, suspicious activity, and negative-balance signals as fraud/risk events.
12. Activate kill switches immediately for deposits, wallet payments, refunds, or adjustments if risk appears.
13. Review /admin/pilot/daily-report before each daily close.
```
